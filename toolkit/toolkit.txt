On reuse — this is now plumbing, not a rebuild. The durable toolkit lives in /home/claude/hfs/ (sprites.py master marking library, build.py config-driven generator, style.css shared stylesheet, preprocess.py split/fold logic) plus make_all.py as the driver. Regenerating every volume is one command: python3 make_all.py. 
To add a page to the nav, you edit one block in nav.js: append to OPERATIONS for a theater, or to TOP for a top-level item (the structure's documented in the file header). No chat required for nav wiring — and since you're pulling in more pages, each one is now "write the page, add one line to nav.js, drop both on Netlify." That directly answers the usage concern.
build.py now emits the placeholder + nav.js script instead of baked nav, so when you regenerate volumes from the toolkit they come out consistent with the hand-built pages. render_topnav and THEATERS are left in place as harmless dead code / documentation
